# Как работают бэкапы

vps-alert не копирует файлы сам. Он управляет [restic](https://restic.net), широко используемой
программой для бэкапов, и добавляет к ней расписание, выгрузку баз данных и управление из Telegram.

## Настройка

```
/paths add /var/www        что сохранять (повторите для каждой папки)
/db                        какие базы выгружать, см. databases.md
/backup → 🎯 Куда          куда: Локально, R2 или Оба
/schedule 1 03:00          когда, см. schedule-and-retention.md
/retention 7 4 6           сколько хранить
```

Настройки хранятся в `/var/lib/vps-alert/settings.json` и не теряются при перезапуске.

## Что происходит во время бэкапа

```
1. Проверки       restic установлен, задан RESTIC_PASSWORD, есть что сохранять
2. Pre-command    BACKUP_PRE_COMMAND из env-файла, если задан
3. Базы данных    каждая выбранная база выгружается в отдельный .sql файл
4. Для каждого хранилища (локально и/или R2):
     a. локально: на диске свободно хотя бы 1 GiB?
     b. только в первый раз: создаётся репозиторий (restic init)
     c. restic backup: сохраняется то, что изменилось, в зашифрованном виде
     d. restic forget --prune: удаляются снапшоты, не подходящие под политику хранения
5. Очистка        .sql дампы удаляются с диска
6. Отчёт          результат отправляется в чат
```

Одновременно выполняется только один бэкап. Если нажать **▶️ Бэкап сейчас**, пока он идёт, бот
сообщит об этом.

## Отчёт

```
✅ Бэкап завершён: my-server (по расписанию)

🗄 Базы данных: выгружено 2/2
✅ postgres · shop: 120.0 MiB
✅ docker:api-db · api: 300.0 MiB

✅ local: снапшот a1b2c3d4, +12.4 MiB нового, всего 3.2 GiB, новых файлов: 48
✅ r2: снапшот e5f6a7b8, +12.4 MiB нового, всего 3.2 GiB, новых файлов: 48

⏱ 1m12s
```

- **+12.4 MiB нового**: данные, которых не было ни в одном прежнем снапшоте, то есть сколько
  на самом деле добавил этот бэкап.
- **всего 3.2 GiB**: размер всего сохранённого.
- Неудачная выгрузка базы или хранилище с ошибкой показываются с ❌ и текстом ошибки, остальное всё
  равно выполняется.
- **⚠️ некоторые файлы не удалось прочитать**: снапшот создан, но часть файлов прочитать не удалось
  (обычно они были удалены во время бэкапа).

## Устаревшие бэкапы

Бэкап, который тихо перестал выполняться, хуже, чем бэкап, который громко падает. Пока расписание
включено, vps-alert проверяет, что бэкап недавно **успешно** выполнился: в пределах интервала
расписания плюс 12 часов (36 часов для ежедневного расписания, 7,5 дня для еженедельного). Если нет,
приходит:

```
⚠️ Нет успешного бэкапа уже 3d 2h: my-server
Последний успешный бэкап: 2026-10-23 03:00
Проверьте /backup и логи: journalctl -u vps-alert
```

- Пока проблема сохраняется, сообщение повторяется раз в сутки, а в отчёте следующего успешного
  бэкапа будет **✅ Бэкапы снова работают.**
- Если успешного бэкапа ещё не было ни разу, отсчёт идёт от первого запланированного запуска.
- Это видно и в ежедневном отчёте. `/mute` временно отключает оповещение, оно придёт после окончания
  mute.

## Куда сохраняются бэкапы

| Хранилище | Где |
|---|---|
| Локально | `/var/backups/vps-alert` (`BACKUP_LOCAL_REPO`) |
| R2 | `<bucket>/vps-alert/` (`R2_BUCKET`, `R2_PREFIX`) |

Локальный бэкап защищает от удалённых или повреждённых файлов. Но он **не** защищает от потери
сервера или его диска, потому что лежит на том же диске. Для этого отправляйте бэкапы ещё и в R2 и
выберите **Оба**.

### Настройка Cloudflare R2

1. В панели Cloudflare откройте **R2** и создайте bucket, например `my-backups`.
2. **Manage R2 API Tokens** → **Create API token** с правами *Object Read & Write*, только для этого
   bucket.
3. Запишите значения в `/etc/vps-alert/vps-alert.env`:

   ```sh
   R2_ACCOUNT_ID=...          # указан на главной странице R2
   R2_ACCESS_KEY_ID=...
   R2_SECRET_ACCESS_KEY=...
   R2_BUCKET=my-backups
   ```

4. `sudo systemctl restart vps-alert`, затем `/backup` → **🎯 Куда** → **Оба**.

Несколько серверов могут использовать один bucket, если у каждого свой `R2_PREFIX`.

## Шифрование и дедупликация

- Всё шифруется с помощью `RESTIC_PASSWORD` ещё до того, как покинет сервер: содержимое файлов, их
  имена, размеры. Тот, у кого есть доступ к bucket, прочитать ничего не сможет. См.
  [пароль бэкапов](backup-password.md).
- Файлы делятся на фрагменты, и каждый фрагмент хранится один раз. Сайт размером 3 GB, который
  меняется на 50 MB в день, добавляет за бэкап около 50 MB, а не 3 GB.

## Ограничения

- Бэкап охватывает выбранные вами папки и базы, а не всю систему. Чтобы восстановить сервер, вы
  заново ставите ОС и приложения, а затем восстанавливаете данные.
- Восстановление выполняется из терминала сервера, а не из бота. См. [восстановление](restore.md).
