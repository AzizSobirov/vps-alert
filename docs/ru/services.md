# Сервисы и сайты

vps-alert может сообщить, когда на сервере что-то перестало работать: сервис systemd, Docker-контейнер
или сайт либо API, который сервер обслуживает. Эти оповещения, как и оповещения о ресурсах,
отключаются через `/mute`.

## Сервисы и контейнеры

Отправьте `/services`. Бот покажет работающие сервисы systemd и Docker-контейнеры с отметкой
🟢 работает или 🔴 остановлен. Нажмите на те, за которыми нужно следить:

```
✅ 🟢 nginx
✅ 🟢 postgresql@16-main
⬜ 🟢 ssh
✅ 🔴 🐳 api (exited)
[🔄 Искать снова]
```

Внутренние сервисы операционной системы (`systemd-*`, `getty`, `dbus`, `cron`, ...) не предлагаются.
Отслеживаемый сервис, который больше не работает, остаётся в списке, чтобы с него можно было снять
отметку.

Каждые 30 секунд проверяется каждый отслеживаемый сервис:

| Событие | Сообщение |
|---|---|
| Остановлен или упал и не поднялся к следующей проверке | 🔴 Сервис **nginx**: упал с ошибкой |
| Контейнер остановился | 🔴 Контейнер **api**: завершился (код выхода 137) |
| Снова работает | ✅ Сервис **nginx** снова работает (простой 4m) |
| 3 и более перезапусков за 10 минут | 🔁 Контейнер **api** постоянно перезапускается: 4 раз за 10 минут |
| Удалён с сервера | ⚠️ Сервис **old** не найден. Если он удалён, снимите отметку в /services. |

Обычный перезапуск занимает несколько секунд, поэтому оповещение приходит, только если сервис всё ещё
не работает при следующей проверке, через 30 секунд. Сервис, который падает и автоматически
перезапускается (`Restart=always`, в Docker `restart: always`), при каждой проверке выглядит рабочим;
этот случай ловит оповещение о постоянных перезапусках.

## Сайты и API

```
/http add https://example.com
/http add https://api.example.com/health
/http rm https://example.com
/http                                    все адреса и их состояние
```

До 20 адресов. Каждый открывается раз в минуту с таймаутом 10 секунд, с переходом по редиректам.

| Событие | Сообщение |
|---|---|
| Две ошибки подряд | 🔴 **https://example.com** недоступен: 502 Bad Gateway |
| Снова доступен | ✅ **https://example.com** снова доступен (простой 6m) |
| Медленнее 5 секунд три раза подряд | 🐢 **https://example.com** отвечает медленно: 6.2s |

Ошибкой считается сбой соединения, таймаут, ошибка DNS или SSL-сертификата, а также HTTP-статус 400 и
выше. Предупреждение о медленной работе отправляется один раз и не повторяется, пока сайт снова не
станет быстрым.

Проверки выполняются с самого сервера, поэтому они ловят упавшее приложение или сломанную настройку
веб-сервера, но не сбой сети между вашими пользователями и сервером. Для этого используйте ещё и
внешний мониторинг; см. [heartbeat](heartbeat.md).
