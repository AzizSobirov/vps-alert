# Пароль бэкапов (`RESTIC_PASSWORD`)

`RESTIC_PASSWORD` — это ключ, которым шифруются все бэкапы. Лежит ли бэкап на локальном диске или в R2,
открыть его может только тот, кто знает этот пароль.

## Что он защищает

Прежде чем что-то записать, restic шифрует:

- содержимое файлов,
- имена файлов и папок,
- размеры, даты и дампы баз данных.

Тот, кто заглянет в ваш bucket R2, будь то сотрудник Cloudflare или человек, укравший ваши ключи R2,
увидит только случайные байты. Он даже не узнает, что существует файл `shop.sql`.

Технически у репозитория есть случайный мастер-ключ, которым шифруются данные (AES-256 с защитой от
подмены). Ваш пароль открывает этот мастер-ключ.

## Откуда берётся пароль

Установщик генерирует случайный пароль из 40 символов, показывает его **один раз** и сохраняет в
`/etc/vps-alert/vps-alert.env` (читать может только root). Посмотреть его снова:

```sh
sudo grep RESTIC_PASSWORD /etc/vps-alert/vps-alert.env
```

Сразу после установки сохраните его в менеджер паролей (Bitwarden, 1Password, KeePass, ...).

## Потерян пароль — потеряны бэкапы

Способа восстановления нет. Без пароля бэкапы не откроет ни restic, ни vps-alert, ни Cloudflare.

Самый опасный случай: сервер умирает, а пароль был только в его env-файле. Бэкапы в R2 целы, но
прочитать их невозможно.

Для восстановления на новый сервер нужны:

1. `RESTIC_PASSWORD`,
2. настройки R2 (`R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET`, `R2_PREFIX`),
3. restic (или vps-alert).

Храните всё это в менеджере паролей.

## От чего он не защищает

| Ситуация | Защищено? |
|---|---|
| Утекли ключи R2 | ✅ Данные нельзя прочитать |
| Украли диск с бэкапами или bucket | ✅ |
| Взломан сам сервер (атакующий получил root) | ❌ И пароль, и ключи R2 лежат на сервере |

Атакующий с root может ещё и **удалить** бэкапы, ведь на сервере есть ключи R2 с правом записи.
Защиты от этого в vps-alert пока нет. Блокировка объектов в bucket — тоже не простое решение: она
мешает и автоматической очистке удалять старые снапшоты. Пока это не решено, самая надёжная
дополнительная копия — та, которую другой компьютер сам забирает с сервера, используя ключи, которых
сервер никогда не видит.

## Правила

- **Используйте на каждом сервере свой пароль.** Установщик делает это автоматически.
- **Не меняйте просто так `RESTIC_PASSWORD` в env-файле, если бэкапы уже есть.** Репозиторий закрыт
  старым паролем, и бэкапы начнут падать с ошибкой `wrong password or no key found`. Меняйте пароль,
  как описано ниже.
- Локальный репозиторий и R2 используют один и тот же пароль, но у каждого свой мастер-ключ.

## Смена пароля

Сначала смените пароль в каждом репозитории, затем в env-файле:

```sh
sudo -s
set -a; . /etc/vps-alert/vps-alert.env; set +a     # загружает текущий пароль

# локальный репозиторий
RESTIC_REPOSITORY=$BACKUP_LOCAL_REPO restic key passwd

# репозиторий R2, если используется
RESTIC_REPOSITORY=s3:https://$R2_ACCOUNT_ID.r2.cloudflarestorage.com/$R2_BUCKET/$R2_PREFIX \
AWS_ACCESS_KEY_ID=$R2_ACCESS_KEY_ID AWS_SECRET_ACCESS_KEY=$R2_SECRET_ACCESS_KEY AWS_DEFAULT_REGION=auto \
restic key passwd
```

`restic key passwd` дважды спрашивает новый пароль. Введите для обоих репозиториев один и тот же
новый пароль, затем:

```sh
nano /etc/vps-alert/vps-alert.env      # RESTIC_PASSWORD=<новый пароль>
systemctl restart vps-alert
```

Меняется только замок мастер-ключа, данные заново не шифруются, поэтому это занимает секунды.
Сохраните новый пароль в менеджер паролей и для проверки нажмите **Бэкап сейчас**.

## Если пароль вообще не задан

Если `RESTIC_PASSWORD=` пустой (например, env-файл писали вручную), ни одного бэкапа ещё не было, а в
меню `/backup` написано **⚠️ в env-файле не задан RESTIC_PASSWORD**. Создайте пароль и перезапустите
сервис:

```sh
openssl rand -base64 30
sudo nano /etc/vps-alert/vps-alert.env      # RESTIC_PASSWORD=<это значение>
sudo systemctl restart vps-alert
```
