# Наблюдение за безопасностью

Помимо [оповещений о входе](alerts.md#оповещения-о-входе), vps-alert следит за тремя признаками атаки
или нежелательного изменения: перебором паролей SSH, изменениями важных файлов и новыми открытыми
портами.

Ни одно из этих оповещений не отключается через `/mute`: как и оповещения о входе, они касаются
безопасности, а не нагрузки.

## Неудачные входы по SSH

vps-alert читает записи sshd из journald (или из `/var/log/auth.log` / `/var/log/secure`, если в
journald их нет) и считает неудачные входы:

- неверный пароль для существующего пользователя,
- попытку входа под несуществующим пользователем,
- соединение, оборванное во время аутентификации (например, отклонённый ключ), если о нём больше
  ничего не записано.

Каждая попытка считается один раз, хотя sshd пишет о ней несколько строк.

Каждые 5 минут проверяется последний час. Когда число неудач достигает порога (по умолчанию 100),
приходит:

```
🚨 Перебор паролей SSH на my-server
1 240 неудачных входов за последний час

Самые активные IP:
  203.0.113.7: 830
  198.51.100.4: 310
Пробовали логины:
  root: 900
  admin: 120
```

Такое оповещение приходит не чаще раза в час, в том числе после перезапусков.

| Команда | Значение |
|---|---|
| `/ssh` | Неудачные входы за последние 24 часа с самыми активными IP и логинами |
| `/ssh threshold 50` | Оповещать от 50 неудач в час |
| `/ssh off` · `/ssh on` | Выключить оповещение или снова включить (100 в час) |

Сервер с открытым в интернет SSH всегда получает какие-то попытки. Они безвредны, пока вход по паролю
выключен или пароли надёжные. Оповещение нужно для необычных волн, а не для фонового шума. Если одни и
те же IP появляются снова и снова, подумайте о [fail2ban](https://github.com/fail2ban/fail2ban) или
разрешите SSH только со своих IP.

## Важные файлы

Эти файлы проверяются каждую минуту:

| Что | Файлы |
|---|---|
| Пользователи и группы | `/etc/passwd`, `/etc/group`, `/etc/shadow` |
| Права администратора | `/etc/sudoers`, `/etc/sudoers.d/*` |
| SSH | `/etc/ssh/sshd_config`, `/etc/ssh/sshd_config.d/*`, `/root/.ssh/authorized_keys`, `/home/*/.ssh/authorized_keys` |
| Задания по расписанию | `/etc/crontab`, `/etc/cron.d/*`, `/var/spool/cron/crontabs/*` |
| Сервисы | `/etc/systemd/system/*.service` |
| Внедрение библиотек | `/etc/ld.so.preload` |

Сообщается о создании, удалении, изменении файла, а также о новых правах или новом владельце, с
подробностями там, где они важны:

```
🛡 Изменились важные файлы на my-server

✏️ /etc/passwd изменён
   👤 Новый пользователь: mallory (uid 1002)
   🚨 Пользователь с правами root (uid 0): toor
✏️ /etc/group изменён
   👥 mallory добавлен в группу sudo
✏️ /root/.ssh/authorized_keys изменён
   🔑 Новый SSH-ключ: SHA256:j4bhX0W+JGIpAlh1rFmC80zrN/pcjTWFFbLrkfl9kqU ssh-ed25519 laptop
🔐 /etc/sudoers права: 0440 0:0 → 0666 0:0
```

- Изменения групп показываются для групп, дающих права, близкие к администраторским: `sudo`, `wheel`,
  `admin` и `docker`.
- SSH-ключи обозначаются тем же отпечатком SHA256, что выводит `ssh-keygen -lf`, так что их можно
  сверить со своими.
- Для `/etc/shadow` показываются только имена изменённых учётных записей. Хеши паролей никогда не
  отправляются и не хранятся; vps-alert хранит короткий хеш каждой строки, чтобы понять, какая запись
  изменилась.
- Содержимое файлов никогда не отправляется.

Первая проверка после установки только запоминает текущее состояние. Изменения, сделанные, пока
vps-alert был остановлен, сообщаются при следующем запуске. Состояние хранится в
`/var/lib/vps-alert/filewatch.json`.

| Команда | Значение |
|---|---|
| `/files` | Состояние: сколько файлов отслеживается и последнее изменение |
| `/files off` | Пауза, например на время плановых работ |
| `/files on` | Снова следить, начиная с текущего состояния, так что изменения за время паузы не сообщаются |

## Открытые порты

Новая программа, слушающая сеть, — частый признак взлома (бэкдор, управляющий порт майнера) или
ошибки настройки (база данных, открытая в интернет).

vps-alert каждую минуту получает список слушающих TCP-портов и занятых UDP-портов. Когда появляется
новый и через минуту он всё ещё открыт, приходит:

```
🔌 Открыт новый порт на my-server

tcp 0.0.0.0:6379 (redis-server)
```

- Однажды увиденные порты запоминаются, поэтому перезапуск сервиса, который закрывает и снова открывает
  свой порт, не вызывает оповещения.
- Короткоживущие сокеты и UDP-сокеты в эфемерном диапазоне (32768–60999), которые используют клиенты
  DNS и NTP, игнорируются.
- `0.0.0.0` или `[::]` означает доступ со всех сетевых интерфейсов; `127.0.0.1` или `[::1]` — только с
  самого сервера.

| Команда | Значение |
|---|---|
| `/ports` | Текущие порты и их программы; 🆕 отмечает порты, которых раньше не было, *(закрыт)* — известные порты, которые сейчас не слушают |
| `/ports off` · `/ports on` | Выключить оповещение или снова включить |
